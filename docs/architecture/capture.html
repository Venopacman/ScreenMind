1Data flow

Three workers run side by side. CaptureWorker takes screenshots and reads window info, a11y text and the URL at the moment of the grab. AnalysisWorker picks frames from a queue, runs OCR and Gemma, and writes the results. AudioWorker watches for calls on its own thread. UiEventRecorder records clicks and app switches by default; it can be turned off.

Order inside one tick

From CaptureWorker._capture_monitor(). The order matters: the focus can move before analysis runs.

  1. Read the focused app and window title (before the grab).
  2. Grab the display. Save it as a JPEG.
  3. pHash dedup. A duplicate is deleted from disk and nothing else happens.
  4. Run the window title through the sensitive-data filter.
  5. On the focused display only: read a11y text and the browser URL right after the grab (_read_focused()). If the focused title changed since step 1, drop both.
  6. Insert an activities row (status='pending') so the timeline shows it at once.
  7. Link pending UI events to this row (activities.user_actions). Waits at most 5 s (LINK_UI_EVENTS_TIMEOUT_S).
  8. Put a CaptureResult on the queue. a11y text and the URL live in this object until analysis or mark_skipped() writes them.

4Data points in detail

4.1 Screenshots

One RGB image per display, saved as JPEG (SCREENSHOT_QUALITY, default 70). The cursor is not included.

macOS

Fallback order

  1. ScreenCaptureKit, capture/sck.py. SCShareableContent lists displays, refreshed every 60 s. SCScreenshotManager grabs one display at native pixel size in BGRA. The handler is awaited with a 3 s timeout. One timeout, or 3 handler errors in a row, start a 5 min cool-down on the screencapture tool. Then one probe goes out, which the capture tick does not wait for. An answer within 3 s brings SCK back. A failed probe doubles the wait (10, 20, 40, then every 60 min). The back-off starts over after 30 min of working SCK. If SCK never gave a frame in the process (G1), it stops for good after 2 failed probes. At most one SCK request is waited for at a time; a lost one costs a few KB and no thread. Log: ScreenCaptureKit ... next try in N min, ScreenCaptureKit answered a probe ...; using it again, Screen grab backend: <name>. /api/status: capture.grab (backend, sck.state on / cooldown / off, sck.next_retry, sck.probing, sck.lost_requests).
  2. screencapture -x -t png -R x,y,w,h, about 0.2 s per display. Used while SCK cools down or fails, or for good after one mss grab took over 5 s.
  3. mss (CGWindowListCreateImage). Deprecated, can hang 30 s.

SCK needs pyobjc-framework-ScreenCaptureKit (a macOS dependency in pyproject.toml) and macOS 14. Without them the log says "ScreenCaptureKit not available; using mss".

Windows

mss only

GDI via mss. The active monitor comes from MonitorFromWindow + GetMonitorInfoW. mss makes the process per-monitor DPI aware, so window rects and monitors are both physical pixels.

Linux

X11 and Wayland

mss on X11. On Wayland, WaylandScreenCapture tries grim (wlroots), then the XDG Desktop Portal (GNOME, KDE).

Displays

CAPTURE_ALL_MONITORS (default on) grabs every display each tick, one row per display. Off: one display, the primary or, with CAPTURE_ACTIVE_MONITOR, the one with the focused window.

Timing (CaptureWorker.run())

The loop wakes every 0.5 s and acts about every 5 s.

  • Active: a "change" grab if 10 s passed since the last saved frame. A "periodic" grab at CAPTURE_INTERVAL (default 40 s, range 10-120).
  • Idle: after 3 ticks in a row with no new frame, only the periodic grab.
  • Event-driven, only with UI events on: request_capture() after an app switch (1.0 s delay), click (1.5 s), Enter in a text field (0.5 s) or a page change (1.0 s). Requests within 3 s merge into one grab; grabs are at least 3 s apart.

Every grab, including the periodic one, goes through dedup. A screen that does not change gets no new row (G4).

Skips. A display whose top app is in BLOCKED_APPS is not grabbed (exact name, lowercase). AUTO_PAUSE_HEAVY_APPS skips the whole tick when the focused app name contains a HEAVY_APPS substring.

4.2 Dedup

capture/dedup.py. One ScreenDeduplicator per display. Hamming distance of imagehash.phash to the last kept frame: 8 or less is a duplicate. The JPEG is deleted and no row is written.

The analysis worker has a second, per-app cache keyed by (app, title[:100]): distance 3 or less is "identical" (copy the last analysis, skip OCR and Gemma); 4-10 and younger than 240 s (chat apps) or 420 s (others) is "minor" (run OCR, reuse Gemma's analysis); more is "full".

4.3 Window and app info

macOS

MacOSAdapter

  • _visible_windows(): CGWindowListCopyWindowInfo(OnScreenOnly | ExcludeDesktopElements), layer-0 windows at least 50x50. Other Spaces and minimized windows are not listed. kCGWindowName is empty without Screen Recording.
  • Not NSWorkspace.frontmostApplication(): it goes stale without an NSRunLoop.
  • get_top_window_in(): first window whose center is on the display. can_find_top_window is True.
  • _best_title(): when the title is empty or the app name (Electron), AXTitle of the first AXWebArea in that exact window (_ax_window_at(), 4 pt tolerance). Sets AXManualAccessibility first.
  • trusts_os_app_name is True.
Windows

WindowsAdapter

  • _app_windows(): EnumWindows from the top of the z-order. is_app_window() drops hidden, minimized, DWM-cloaked, tool, click-through, no-activate, always-on-top, shell, untitled and tiny windows.
  • App name: exe name without extension (process_name()). For UWP apps inside ApplicationFrameHost, the child's process.
  • _best_title(): when the title is only the app name, the name of the window's top on-screen UIA Document.
  • trusts_os_app_name is False.
Linux

xdotool on X11, compositor IPC on Wayland. No per-display lookup, no window list.

4.4 Accessibility text

Read by A11yExtractor.extract_text() at grab time, for the focused display only (G7).

macOS

_walk_ax_tree()

  • Root: AXFocusedWindow of the front app. Browsers: only page areas from _ax_page_areas(), not DevTools or extension pages. Tab strip and address bar are not read.
  • Skips AXMenuBar, AXMenuBarItem, AXMenu, AXMenuItem, subroles AXLandmarkNavigation, AXLandmarkComplementary. Never reads AXSecureTextField.
  • Reads AXTitle and AXValue. Values over 4,000 chars give only their visible part (AXVisibleCharacterRange + AXStringForRange).
  • Drops repeated lines and prefix/suffix repeats.
  • Limits: depth 8, reset at each AXWebArea with limit 45; 4,000 nodes; 300,000 chars. AX timeout 1 s.
Windows

_extract_uiautomation()

  • Browsers: only on-screen page Documents (page_documents()), not DevTools, extension panels or Chrome's .top-chrome side panels. Tabs, toolbar and address bar are not read. No page Document = no a11y text, OCR instead.
  • Other apps: native walk _walk_tree() (depth 8, 500 lines). Skips menus, title bars, scroll bars and native chrome by type: ButtonControl, SplitButtonControl, ToolBarControl, StatusBarControl, TabItemControl. Then its web Documents (Electron), read whole.
  • Web Documents: one UIA cache request (_cached_tree(), 20,000 nodes, depth 200), read by web_text(): on-screen only, skips navigation/complementary landmarks, menus, passwords, URLs and link targets.
  • Native controls: Name and value; editable Edit/Document give visible lines only. Never reads IsPassword fields.
  • Drops repeats (_repeats(), as macOS). Cap 300,000 chars. UIA timeouts 1 s (CUIAutomation8).
  • Fallback without uiautomation: EnumChildWindows + GetWindowTextW.
Linux

AT-SPI via pyatspi.

How analysis uses it. _a11y_is_content(): at least 200 chars after removing the title and the app name, and not mostly repeats. macOS and Linux also drop English chrome markers and menu-word lines; Windows skips that, since its walker leaves chrome out by type in any UI language. Then it replaces OCR. Otherwise OCR runs, with a11y text up to 500 chars in front. The path is only logged; analysis_method stores the analysis tier (full:fast, cache:minor...). Only OCR writes ocr_boxes. The a11y text has no column of its own; it ends up in activities.ocr_text (G12).

4.5 Browser URL

_get_browser_url() → adapter().get_browser_url() → sanitize_url(). Focused display only.

macOS

Only when the front app is in BROWSER_APPS. _ax_page_url() takes the AXURL of the page areas. Exactly one http(s) URL must remain, else None. Iframes are not visited.

Chrome ignores AXManualAccessibility. After a reboot, with no other a11y client, Chrome has no AXWebArea: no URL and no page text (G8). Firefox is untested (G9).

Windows

Only when the foreground exe is in _BROWSER_EXES. _window_documents() finds every UIA Document. pick_page_document() keeps top-level, on-screen Documents that are not DevTools, extensions or Chrome's side panels. Exactly one must remain with an http, https or file:/// URL. Chrome and Firefox build the tree lazily. sanitize_url() then drops file://.

Linux

None.

Per window: get_window_url(pid, bounds) reads a browser window that is not in front. macOS only; used for call room URLs (G16). Not used: URLs found in OCR text. They go to Gemma as a hint, but active_url is only the browser's own URL.

4.6 OCR

  • engine/ocr.py, RapidOCR on ONNX Runtime, CPU only. EasyOCR is gone since 4cb9030.
  • Detection PP-OCRv6 tiny. Recognition PP-OCRv5 mobile, one model per frame.
  • OCR_LANGUAGES (default en) picks the recognizer in _rec_model(). Mixed scripts: a Cyrillic model wins. So one script per frame (G14).
  • Readings under 0.5 confidence are dropped. _fix_lookalikes() makes mixed Cyrillic/Latin words one script.
  • Models (~15 MB) in ~/.screenmind/models/ocr.
  • onnxruntime: memory pattern and arena off, OCR_THREADS threads (default 2). Less memory, about 40% less CPU per frame.
  • Runs in the analysis worker. Skipped when a11y text is real content, and on "identical" cache hits.
  • Output: text and boxes (ocr_boxes JSON). organize_ocr_text() groups boxes into regions (organized_text).

4.7 UI events

On by default (UI_EVENTS_ENABLED=true) with UI_EVENTS_TYPES=click,app_switch. Typed text, clipboard and window_focus are opt-in, because text and clipboard can hold private content (G31). A settings.json saved before this default keeps its own value.

OS hook thread -> queue.SimpleQueue -> enricher thread -> ui_events table
                                              +-> CaptureWorker.request_capture()
macOS

MacOSUiEventBackend

  • CGEventTapCreate(kCGSessionEventTap, kCGTailAppendEventTap, ListenOnly) for mouse down and key down, on its own CFRunLoop thread. Without Input Monitoring that fails, so it retries mouse-only: clicks yes, typing no. Re-enabled if macOS disables it. Callback errors and re-enables are counted (tap_stats()).
  • Characters: CGEventKeyboardGetUnicodeString. Cmd/Ctrl = shortcut.
  • Elements: AXUIElementCopyElementAtPosition, system-wide AXFocusedUIElement. Walks up to 3 parents to the control. AX timeout 0.25 s.
  • Clipboard: NSPasteboard.changeCount() every 1 s and 0.3 s after Cmd+C/X. Skips org.nspasteboard Concealed, Transient, AutoGenerated types.
Windows

WindowsUiEventBackend

  • SetWindowsHookExW(WH_KEYBOARD_LL / WH_MOUSE_LL) with a GetMessageW loop. Injected events skipped. 10 s watchdog re-installs a silent hook.
  • Characters: ToUnicodeEx flag 0x4, own dead-key composition.
  • Elements: UIA via uiautomation. Roles normalized (EditControl → Edit).
  • Clipboard: GetClipboardSequenceNumber. Skips ExcludeClipboardContentFromMonitorProcessing, CanIncludeInClipboardHistory=0, CanUploadToCloudClipboard=0.
  • x/y are physical pixels here, points on macOS.

Shared recorder (UiEventRecorder)

  • Front window polled every 0.5 s. New pid or app = app_switch. Title change with a new browser URL = window_focus, even when that type is off.
  • Typing kept only in text inputs (TEXT_INPUT_ROLES) that are not read-only. TextBuffer groups keys per field; Enter, Tab, arrows, Escape, a click, an app switch or 2 s idle end a chunk; max 500 chars.
  • Password fields store [password field].
  • Nothing is recorded while capture is paused or in BLOCKED_APPS. Skips are counted (status()["skipped"]).
  • Console logs make silent failures visible: "UI events are off" at startup, the enabled types on start, missing Accessibility or Input Monitoring, the first input event, a warning if no click or key arrives in 2 min, events lost in the hook, a stopped hook, and a 10-minute summary of input, stored rows and skips.
  • Every text field (names, values, typed text, clipboard up to 1,000 chars, window titles) goes through the sensitive-data filter before it is queued. A label typed before a pause ("pwd -") is checked with the next chunk. URLs through sanitize_url().
  • Backend calls run without the recorder lock; flush_for_capture() waits at most 2 s. Rows written in batches every 2 s. At each saved frame, attach_ui_events() links unlinked events to the new row. format_user_actions() makes at most 10 lines (1,200 chars) in activities.user_actions, which go into the Gemma prompt. With several displays, all go to the first frame of the tick (G21).

4.8 Calls and meetings

workers/audio_worker.py and workers/call_detection.py. Calls are tracked always. Transcription is off by default (MEETING_TRANSCRIPTION=false).

Detection, own thread, every 5 s, also while capture is paused

  • Input: list_visible_windows() and get_mic_apps().
  • macOS macos_audio.mic_apps(): CoreAudio kAudioHardwarePropertyProcessObjectList, then kAudioProcessPropertyIsRunningInput and the pid per process. Each pid maps to its outermost .app name ("Slack Helper" → "Slack"). Same signal as the orange mic dot. No mic permission. macOS 14+. Windows Linux return None.
  • match_call() rules for MEETING_APPS (default zoom,teams,meet,webex,slack,discord): Meet = browser window titled "Meet - ..."; Zoom = "Zoom Meeting/Webinar" title or Zoom on the mic; Teams/Webex = name plus "meeting"/"call" in the title, or on the mic; Slack = "huddle" or on the mic; Discord = on the mic only; other keywords = owner or title contains it. Native apps on the mic count with no visible window.
  • Starts after 2 detections in a row. Ends when not seen for CALL_END_GRACE_S (default 120 s); the stored end is the last time seen. A title change (Meet's 🔊 marker), a mute or a hidden window shorter than the grace keeps the same row.
  • Restarts: shutdown ends the call at the last time seen. At a call start, _resume_recent() reopens the last meetings row if it ended less than the grace before, has no transcript, and same_call() matches: same app_name; room URL if both known; else, for browser calls, the title without markers (normalize_title(): emoji, "* ", " - N new items", " [Main]"); else the app alone. Fixes one Meet call saved as rows 4 and 5 around a restart (2026-10-07).
  • Stored: meetings.start_time, end_time, app_name, window_title, url (v10), duration_minutes (every 60 s). Browser room URL from get_window_url() + sanitize_url(), retried every 30 s.

Transcription, when on and the model has an audio encoder

  • sounddevice records the mic and, if found, a device named "loopback" or "stereo mix". 16 kHz, 15 s chunks.
  • Each chunk goes to Gemma via llama-server (input_audio). Transcript and summary go to meetings.transcript and meetings.summary.
  • macOS has no such device by default: mic side only (G18).

4.9 Analysis

analysis_worker.py → analyzer.py (GemmaAnalyzer) → llm_client.py → llama-server at LLAMA_SERVER_HOST (default http://127.0.0.1:5809, /v1/chat/completions). Default model gemma-4-e2b, context 6,144 tokens. Modes: fast (default, no thinking, 500 tokens out), balanced (thinking, 1,024), merged (thinking + layout, 1,800).

Retention

RETENTION_DAYS (default 7, 0 = forever). cleanup_old_data() deletes activities and their JPEGs, ui_events and meetings older than the cutoff. It runs once, at startup (G24).

Encryption

ENCRYPTION_ENABLED (default off) encrypts each JPEG in place with Fernet. The key is in the OS keyring via keyring, with a 0600 file copy. The DB is never encrypted: typed text, OCR text and URLs are plain text (G23).

Export

GET /api/export builds a zip for a user and a date range: one folder per day, one text file per session (split by idle gaps), JSONL copies and the screenshots. Only status='ok' rows go out, and URLs and text are filtered again on the way. Format: docs/export-format.md in the repo.

Who gets the prompt on macOS

TCC grants a permission to the "responsible process", not to a Python package.

  • Terminal.app (the user's main instance): Terminal gets Screen Recording, Accessibility and Input Monitoring. Every script run from Terminal gets them too.
  • A Claude session: Claude.app starts children through a disclaimer helper, so Python is its own responsible process. CGPreflightScreenCaptureAccess() says True, but SCK never answers and mss hangs 30 s. Only the first SCK call of the process answers (the display list); later ones hang too. Only screencapture works (G1).
  • The venv's Python directly (LaunchAgent, IDE): the prompt names "Python" or the IDE.
  • A future signed ScreenMind.app would show "ScreenMind" (G22).

Accessibility and Input Monitoring are requested only from the UI events settings (POST /api/ui-events/permissions). Screen Recording is never requested explicitly; macOS asks on the first grab.

Windows No prompts. Elevated (admin) windows are likely out of reach because of UIPI. Not tested (G25).

10How to update

  • Same-commit rule. A change to capture code (screenmind/capture/, capture_worker.py, audio_worker.py, call_detection.py, a11y_extractor.py, ocr.py, what analyzer.py sends to Gemma), a platform adapter (screenmind/platform_support/), a privacy filter or a DB migration updates docs/architecture/capture.md in the same commit.
  • Update the matrix row, the detail section and the gap table. Close a gap by deleting its row and naming the commit. Keep gap ids stable; don't reuse a deleted id.
  • A new migration: add its columns to section 5 with (vN) and update "the latest is vN".
  • Mermaid: keep labels in double quotes and check the diagram renders.
  • Then sync docs/architecture/capture.html (this page) with the same facts and republish it to the same Artifact URL. Both files use the same section numbers and gap ids.
